# 第八章 游戏上线

上线把开发环境中的作品变成玩家可以找到、打开并理解的产品。代码能在本机运行只是起点。你需要一个固定版本、一份完整构建、准确的发布页面和能够处理问题的更新方式。

## 发布前固定承诺

列出本版支持的设备、浏览器、操作方式、保存能力、预计体验范围和已知限制。检查这些说明是否与实际构建一致。若只验证了桌面浏览器，不要仅因为页面能缩小就宣称完整支持手机。

给发布版一个版本号和可定位的 Git 提交。保存生成步骤与依赖锁文件，让同一份源码能重新构建。资源清单与许可说明跟随版本，防止发布时漏掉字体、音频或图片。

先给一小组测试者提供候选版本，确认构建环境与本地预览没有差异。若发现严重问题，继续修复候选版本；正式发布之后再修，需要同时面对玩家与存档兼容。

## 生成独立的发布目录

构建输出只包含运行所需文件。不要上传 `.git`、本机配置、账号凭证、原始参考素材和调试存档。检查资源路径、大小写、编码与加载失败提示。

浏览器游戏应从 HTTP 服务检查，不能只双击文件。模块导入与资源请求在不同环境下可能表现不同。使用相对路径，有利于部署到项目子目录；实际配置仍要根据所用构建工具验证。

如果游戏依赖外部 CDN，测试不可访问时的行为，并评估能否将必要资源一并打包。避免把基础游玩依赖于开发者本机地址或临时服务。

## 主线实践发布到 itch.io

itch.io 支持 HTML5 游戏在浏览器中运行。官方文档要求多文件项目打包为 ZIP，包含作为入口的 `index.html`，并提醒使用相对资源路径、正确大小写和 HTTPS 外部请求。[HTML5 发布说明](https://itch.io/docs/creators/html5)

一个可执行的发布顺序是：创建项目，填写名称与简述，选择 HTML 游戏类型，上传构建 ZIP，设置嵌入尺寸与启动方式，预览检查，再公开页面。实际按钮名称与限制以上线时的官方界面为准。

预览时检查首次加载、开始按钮、音频解锁、全屏、缩放、存档和重新进入。让没有项目缓存的人打开链接，确认不是只有开发者环境能运行。

本书讲解的是游戏发布流程。本书自己的阅读站点使用 GitHub Pages，两个站点的作用不同：一个提供游戏，一个提供书稿。

## 发布页面表达玩家会经历什么

第一句话描述行动与特色，例如：“调整菜单与厨房配置，解决每天不同的经营瓶颈，把街角小店经营下去。”接着用几张真实截图展示准备、营业、结算与成长。

截图使用实际发布版，保留关键界面。封面负责让人认出作品，截图负责说明体验，短视频负责展示变化。不要把概念图中尚未实现的场景当作实机内容。

页面应包括操作方式、保存说明、语言、版本、已知限制、反馈入口与素材署名。若游戏免费、付费或采用自愿支持，明确玩家实际得到什么。定价需要结合内容、目标用户与平台条件，不存在适用于所有小型游戏的固定公式。

上线前就可以展示开发进度和征集测试者。每次展示围绕一个可见变化，例如“菜单改变了排队情况”，比只发一张代码截图更容易传达游戏体验。对外沟通应尊重所在社区规则。

## 桌面与 Steam 作为扩展路线

桌面发布还涉及导出、平台差异、安装与启动、存档位置、打包与签名等问题。不能仅把浏览器文件压成 ZIP 就认为已经完成桌面适配。先选一个目标系统验证，再扩大支持范围。

Steam 有独立的入驻、商店、构建和审核流程。涉及费用、时间窗口和地区要求时，直接检查当前官方资料，不把容易过期的数字当作正文常量。[Steamworks 入门资料](https://partner.steamgames.com/doc/gettingstarted)

使用 AI 辅助编程与发布玩家会接触的 AI 生成美术、音频或文本，应按平台当前表单分别判断和说明。Steam 的内容调查关注随游戏交付或运行时生成、供玩家消费的内容，并对运行时生成内容提出额外说明要求。[内容调查](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)

准备发布资料时保留生成内容与第三方资源的来源记录，如实填写，不用“AI 做的”代替具体说明。对资产的使用权有疑问时，应在发布前解决或替换。

## 更新与回退也属于上线

保留上一版构建。新版本先在预览环境验证，再替换公开版本。若更新改变存档结构，迁移前保留备份，测试旧档，并说明不可逆变化。

回退程序文件不一定能回退已经迁移的存档。兼容计划要同时考虑代码与数据。若某次更新存在数据风险，先缩小范围，优先修复关键问题，再推进结构调整。

给玩家一个反馈入口，说明怎样附版本号、复现步骤和截图。默认不要收集不必要的个人信息；需要统计或日志上传时，明确范围和用途，并检查适用要求。

## 本章实践与验收

发布一个测试页面，让新玩家从公开链接完成一轮经营。检查页面信息、文件版本与实际行为一致。保存发布提交、构建文件、页面链接和检查记录。

完成标准是玩家能够找到、启动、理解并体验本版承诺的内容，你也有办法修复与更新。公开链接之后的第一次反馈，将成为下一章的输入。
